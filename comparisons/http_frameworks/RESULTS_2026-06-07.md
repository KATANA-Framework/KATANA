# Cross-Framework HTTP Benchmark — Honest Run (2026-06-07)

KATANA vs actix-web, axum, drogon, ntex. **Fair, apples-to-apples conditions** — see
*Methodology* below. wrk ran on the same host (no separate load box available),
mitigated by pinning the server and the load generator to disjoint physical cores.

## Environment

| Key | Value |

## Build optimization (the fairness fixes that make this honest)

Before this run the competitors were built with stock `cargo --release` / plain CMake
Release, while KATANA shipped with `-O3 -march=native` + LTO — an unfair build gap that
artificially flattered KATANA. Fixed here:

| Target | Build flags used in this run |
|--------|------------------------------|
| KATANA (fastpath + router-only) | `-O3 -march=native -mtune=native` + IPO/LTO (Release `bench` preset — **not** the old debug `examples` preset) |
| actix-web / axum / ntex | `[profile.release] lto = "fat", codegen-units = 1, opt-level = 3` + `.cargo/config.toml` `rustflags = ["-C","target-cpu=native"]` |
| drogon | app TU: `-O3 -march=native -mtune=native` + IPO (libdrogon/libtrantor are the stock distro 1.9.12 build) |

Endpoint/payload parity verified: every server returns `Hello, World!` on `GET /` and the
numeric sum on `POST /compute/sum` with identical 1..1024 validation. (KATANA serializes
the sum as `15`, others as `15.0` — both valid JSON, ~2-byte difference, negligible.)

`katana-fastpath` = hand-written fast dispatch; `katana-router-only` = the general router
(the fair lane vs actix/axum's general routers). They land within noise of each other, so
KATANA's result is **not** a hand-tuned-router artifact.

## Honest takeaways

- **Compute path (the real framework work — JSON parse + validate + serialize):** KATANA
  leads everywhere on both throughput and p50, by a wide margin (≈1.5× actix at d10, ≈1.7×
  at d40; 4–8× drogon/ntex).
- **Hello path (bare static response):** KATANA and actix are neck-and-neck at the top.
  **actix actually wins Hello-d1 (420K) and Hello-d10 (3.20M vs 3.15M);** KATANA edges
  ahead at Hello-d20 and has noticeably tighter pipelined latency (p50 702 vs 1138 µs at d20).
- **axum, drogon, ntex** trail on every scenario.
- **Hello keep-alive (d1)** clusters around 400–420K for everyone — it is loopback-RTT-bound,
  not a framework signal.

## Caveats (disclosed)

- Same-host load generation (wrk shares the box). Pinning to disjoint physical cores reduces
  but does not eliminate interference; absolute latency is loopback-optimistic.
- `katana-fastpath` uses hand-written dispatch; use `katana-router-only` for the
  general-router-vs-general-router comparison.
- SO_REUSEPORT accept model differs (KATANA/actix/ntex use it; axum/drogon do not) — a real
  capability difference, relevant under 512 same-host connections.
- median-of-2 with short durations: directional, not publication-grade precision. Raise
  repeats/duration for a final report.
